# CineTracker Android 0.0.97 HOTFIX 8

P0 post-login freeze recovery. No feature removal.

## Root cause
- `patch-v068-v097.js` registered a document-wide `MutationObserver`.
- Its callback called `footer97()` on every observed DOM mutation.
- `footer97()` reassigned the `.ct97-version` `textContent` even when the value was already identical.
- That write generated another observed `childList` mutation, causing an endless MutationObserver microtask loop immediately after the authenticated Home rendered.
- Supabase authentication and the initial profile request could therefore return HTTP 200 while the UI thread remained starved before the normal post-login hydration completed.

## Recovery
- Adds a narrowly scoped observer guard immediately before the v97 runtime.
- Only self-generated mutations inside `.ct97-version` are ignored; the remaining v97 observer behavior and features stay active.
- Makes HOTFIX 8 version text updates idempotent.
- Preserves all HOTFIX 7 startup/session protections.
- Preserves the full v97 feature layer, including Pra Você, Calendário, episode enhancements and Bingers import.

## Validation
- Real Chrome reproduces accepted password login and requires the authenticated Home to become visible.
- The same test requires post-login hydration to start requests for `media_overrides`, `recommendation_history` and `episode_progress`.
- Browser error count must remain zero.
- The exact Android embedded HTML is run through the same real-browser post-login proof after every script is inlined.
- APK package identity, signature and embedded runtime are verified before release.

## Falha original e correção de `watch_history`

A falha original do lote era PostgREST `PGRST102 / All object keys must match`. O payload de `watch_history` misturava objetos de filme sem `season_number`/`episode_number` e objetos de episódio com essas chaves.

Correção aplicada: registros de filmes carregam explicitamente `season_number: null` e `episode_number: null`, garantindo shape homogêneo no bulk upsert.

A tentativa legada import ID 5 foi encerrada como falha (`LEGACY_PIPELINE_STALLED`) em vez de permanecer indefinidamente em `processing`.

## HOTFIX 16 — importador resiliente preservado

A Edge Function `ct-import-bingers-user` v8 inclui:

- autenticação bearer validada no backend;
- erros tipados de autenticação, transientes e permanentes;
- `client_run_id` para begin idempotente e retomada segura;
- contrato de cursor e reconhecimento de replay de lote;
- validação de linhas e deduplicação;
- nenhum preenchimento artificial de data assistida;
- limpeza restrita a dados originados do Bingers/importação anterior;
- proteção de estados manuais;
- verificação de total esperado, cursor e contagem exata de histórico antes de concluir;
- erros permanentes alteram o import para `failed` e armazenam código/mensagem de falha.

## Classificação de séries confirmada pelo usuário

O usuário confirmou que todas as séries do conjunto revisado estão em dia: quando encerradas/canceladas devem ser `Completed`; quando ainda podem receber episódio/temporada devem ser `UpToDate`.

Estado reconciliado:

- **155 Concluídas** (`Completed`);
- **47 Em dia** (`UpToDate`);
- **25 Em andamento** (`InProgress`);
- **533 Não iniciadas** (`AddedToWatchlist` sem histórico);
- **227 séries com histórico**.

O Perfil passou a separar explicitamente `Concluídas`, `Em andamento`, `Em dia` e `Não iniciadas`. O texto de episódios usa o número de séries com histórico, evitando confundir histórico com status atual.

## Correção das séries falsamente iniciadas pelo Bingers

Foram identificadas séries que o Bingers marcava como iniciadas embora possuíssem zero episódios vistos. Isso é tratado como erro de origem.

Regra vigente:

- série importada com zero histórico real de episódios não pode permanecer `InProgress`;
- deve permanecer/retornar a `Não iniciadas`, salvo decisão manual explícita do usuário.

Proteções de banco adicionadas:

- `ct_guard_bingers_import_inprogress()`;
- `ct_cleanup_bingers_zero_history_inprogress()`.

Validação posterior confirmou **0 séries `InProgress` sem histórico**.

## Regra de governança incorporada

A partir desta release, toda nova unidade lógica de mudança deve:

- incrementar versão;
- registrar código e documentação no GitHub;
- atualizar `CHANGELOG.md`, `PROJECT_STATE.md`, `VERSIONS.md`, README(s) e release note;
- atualizar arquitetura/segurança se afetadas;
- manter migration para alteração de banco;
- manter código-fonte de Edge Function versionado;
- possuir registro de validação;
- não afirmar deploy, build, publicação ou teste real sem evidência.

Detalhes: `docs/DEVELOPMENT_RULES.md`.

## Débitos conhecidos / não mascarados como concluídos

1. Mídias importadas sem TMDB real podem usar identificadores substitutos negativos; chamadas ao `tmdb-proxy` com esses IDs já produziram 404. O cliente deve impedir consulta TMDB para ID substituto ou o modelo de IDs deve ser redesenhado.
2. Segurança Supabase possui advisories abertos para funções `SECURITY DEFINER` expostas a `anon`/`authenticated` e proteção de senha vazada desativada; revisar antes de considerar hardening encerrado.
3. Tabelas/staging de importação históricas devem continuar sob revisão de RLS/policies; não habilitar RLS cegamente sem política compatível com o fluxo.
4. Deploy Web em produção e APK Android são estados independentes do código em `main` e precisam de confirmação própria.

# CineTracker v0.99.2 — FIX2 consolidado 0.99.1 + 0.99.2

## Situação
A primeira publicação do 0.99.2 FIX foi invalidada após evidência real de **travamento completo na Web e no APK Android**. A versão lógica permanece `0.99.2`, pois esta unidade ainda não estava funcionalmente encerrada.

## Causa raiz do congelamento
O runtime continha dois fluxos de `MutationObserver` que reconciliavam rodapé/cabeçalhos após mutações do DOM. Em `patch-v093-v0992.js`, `footer()` atribuía `textContent` em todas as notificações. Em `patch-v095-v0992-fix.js`, `canonicalFooter()` e `decorateProfileHeaders()` também podiam atribuir `textContent` repetidamente.

Mesmo quando o texto era igual, a atribuição substituía o text node, gerava outro `childList MutationRecord` e reativava o observer. O ciclo observer → DOM → observer saturava a main thread no navegador e na WebView Android.

## FIX2 de estabilidade
- Nova camada final `apps/web/patch-v096-v0992-unfreeze.js`.
- Marker: `__ct0992UnfreezeLoaded` / `fix2-idempotent-dom-mutation-guard`.
- O patch torna atribuições de `Node.textContent` com valor idêntico um no-op, interrompendo o churn recursivo sem remover a reatividade necessária.
- O guard entra antes dos observers atrasados da pilha 0.99.2 começarem a observar `#app`.
- Refresh inicial é coalescido com `requestAnimationFrame`.
- Cache Web rotacionado para `ct-web-0.99.2-fix2`.

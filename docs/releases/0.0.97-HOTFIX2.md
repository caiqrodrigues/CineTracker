# CineTracker 0.0.97 HOTFIX 2

## Motivo

O HOTFIX 1 corrigiu o fluxo de autenticação, mas a troca do carregamento Android para `WebViewAssetLoader` causou uma regressão real em dispositivo: o aplicativo podia abrir apenas uma tela preta, sem chegar à tela de login.

## Correção

- Remove `WebViewAssetLoader` do caminho de inicialização.
- Remove `appassets.androidplatform.net` do runtime Android.
- Mantém o build Web validado dentro do APK.
- Converte o build Android em um HTML autocontido, com os scripts locais embutidos no próprio `index.html`.
- Carrega o HTML embutido com `WebView.loadDataWithBaseURL`, usando a origem HTTPS normal de `mycinetracker.vercel.app`.
- Mantém `localStorage`, cookies e comportamento de origem compatíveis com as versões anteriores.
- O WebView fica visível desde o início.
- O bootstrap Android renderiza a interface antes de aguardar restauração de sessão, evitando documento vazio durante chamadas de rede.
- O HOTFIX 2 não restaura o estado de navegação do WebView do HOTFIX 1, evitando reabrir a URL `appassets` quebrada depois de atualização sobre a instalação existente.
- Se o runtime embutido não produzir a tela de login/Home, há fallback automático para a Web remota em vez de permanecer em tela preta.
- O bundle Android não registra Service Worker.
- FIX 7 e preboot FIX 7 continuam fora do runtime de autenticação.

## Autenticação preservada

A recuperação feita no HOTFIX 1 continua ativa:

- login válido abre a Home antes da hidratação pesada;
- banco e recomendações carregam em segundo plano;
- autenticação e restauração possuem timeout;
- falha de storage não invalida sessão válida em memória;
- duplo submit é bloqueado;
- credencial inválida não apaga os campos.

## Validações de CI

O pipeline exige:

- suíte de regressão da autenticação;
- build Web;
- geração do HTML autocontido Android;
- presença de `window.__ctAuthRecovery = 'v97-base'`;
- presença de `window.__ctAndroidBundle = 'hotfix2-inline'`;
- ausência de scripts locais externos no HTML Android;
- ausência do FIX 7;
- ausência de `WebViewAssetLoader` e `appassets.androidplatform.net` no Android;
- presença de `loadDataWithBaseURL`;
- presença do watchdog/fallback de inicialização;
- build Gradle;
- confirmação do runtime embutido dentro do APK;
- assinatura e package Android;
- `versionCode 980`;
- `versionName 0.0.97 HOTFIX 2`.

## Observação

O fallback remoto existe apenas como rede de segurança contra falha de inicialização. O caminho principal continua sendo o runtime recuperado empacotado no APK.

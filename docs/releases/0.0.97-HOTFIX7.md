# CineTracker Android 0.0.97 HOTFIX 7

P0 startup recovery only. No new features.

## Root cause addressed
- A persisted legacy Supabase session can poison startup across Web and Android builds that share the same origin/storage.
- The Web bootstrap previously waited for session restoration before painting login, so a bad or stalled auth restoration could leave the application apparently dead.

## Recovery
- Paints the login UI before any session restoration attempt.
- Performs a one-time removal of only `cinetracker_session` using the `cinetracker_p0_session_reset_hotfix7` migration marker.
- Does not clear watch history, library, preferences, overrides or imported data.
- Caps session restoration at 6.5 seconds and falls back to login instead of blocking the UI.
- Keeps login/refresh isolated from stale Authorization headers and validates JWT shape.
- Android embeds the exact validated Web bootstrap and does not fall back to Vercel at startup.
- Every inlined Android script is syntax-compiled before release.
- Real Chrome CI requires login to be visible within 1 second even with a poisoned persisted session and deliberately hung Auth requests.

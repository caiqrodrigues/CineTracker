## Causa raiz do travamento do FIX anterior
A revisão do runtime publicado encontrou um ciclo recursivo de DOM:

1. `patch-v093-v0992.js` possui `MutationObserver` para reatividade/importação;
2. seu helper `footer()` atribuía `f.textContent='CineTracker • v0.99.2'` em toda notificação, mesmo quando o conteúdo já era idêntico;
3. atribuir `textContent` substitui o text node e produz um novo `childList MutationRecord`;
4. o próprio observer era acionado novamente;
5. `patch-v095-v0992-fix.js` adicionou outro observer que também chamava `canonicalFooter()`/`decorateProfileHeaders()` com atribuições de `textContent`;
6. o resultado prático foi um loop de MutationObserver/DOM que saturou a main thread tanto no navegador quanto na WebView Android.

Esse defeito não era detectado pelos checks antigos porque eles verificavam presença/sintaxe/markers, não churn recursivo em runtime.

## Correção FIX2
- [x] Criado `patch-v096-v0992-unfreeze.js` e carregado **depois** de 0.99.1, 0.99.2 e do FIX anterior.
- [x] O patch instala guarda idempotente para `Node.prototype.textContent`: atribuição de valor idêntico passa a ser no-op, impedindo que os observers históricos produzam mutações infinitas.
- [x] O guard é instalado antes dos observers atrasados de 250/500 ms começarem a observar `#app`.
- [x] Refresh inicial é coalescido por `requestAnimationFrame`, evitando rajadas redundantes.
- [x] Marker obrigatório: `__ct0992UnfreezeLoaded` / `fix2-idempotent-dom-mutation-guard`.
- [x] Cache Web rotacionado para `ct-web-0.99.2-fix2`.
- [x] Android mantém `versionName 0.99.2`, mas sobe para `versionCode 9913` porque o APK defeituoso `9912` chegou a ser publicado e não pode ser reutilizado como atualização.
- [x] Bundle Android FIX2: `v0.99.2-fix2-unfreeze-991-992-authoritative`.
